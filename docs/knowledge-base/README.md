## Authority and conflict resolution

1. The accepted customer order, signed service agreement, approved customer configuration and current account billing records govern that customer's service.
2. Production Worker behavior, D1 schema/migrations, deployed bindings and provider account configuration determine what is technically live.
3. Current source on approved main describes intended implementation, but source code alone does not prove deployment or end-to-end operation.
4. This knowledge base explains the operating standard and must be updated when the source of truth changes.
5. If sources disagree, stop and investigate. Do not silently choose the more convenient statement or make a customer-facing promise.

## Evidence labels

- **Verified in source:** Code, schema or configuration was inspected.
- **Configured in production:** The relevant production binding, setting or deployment was inspected.
- **Tested end to end:** The complete real workflow was executed and its outcome verified.
- **Not verified:** Credentials, test data, provider access or a live test are missing.
- **Planned:** A design or proposal exists but is not implemented.
- **Customer-specific:** Depends on the accepted order, approved configuration or enabled integration.

Never convert “verified in source” into “live” or “tested.”
